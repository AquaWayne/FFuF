# Аудит сайта: ffuf + пассивные проверки

Скрипты пассивного аудита и генерации отчётов поверх [ffuf](https://github.com/ffuf/ffuf).

**Автор обёрток, HTML-отчёта и CSV: [AquaWayne](https://github.com/AquaWayne).**

Документация оригинального ffuf лежит в [README.ffuf.md](README.ffuf.md), файлы проекта не изменялись.

## Авторы

**Оригинальный проект ffuf (Fuzz Faster U Fool)** написал **Joona Hoikkala**
([joohoi](https://github.com/joohoi)), проект распространяется по лицензии MIT.

- Репозиторий: https://github.com/ffuf/ffuf

Всё, что делает перебор путей и параметров, это его работа. Здесь добавлены только
обёртки на PowerShell и генератор отчёта. Если форкаете или публикуете, сохраняйте
файл LICENSE и ссылку на автора.

**Скрипты этой части** написал [AquaWayne](https://github.com/AquaWayne): `audit.ps1`,
`audit.cmd`, `scan.ps1`, `scan.cmd`, генератор HTML и CSV.

## Что добавлено

| Файл | Назначение |
|---|---|
| `audit.cmd` / `audit.ps1` | пассивный аудит: заголовки, CSP, cookie, TLS, формы, SPF и DMARC, оценка CVSS, HTML-отчёт и CSV для трекера |
| `scan.cmd` / `scan.ps1` | обёртка над ffuf: словарь по умолчанию, лимит скорости, файл отчёта |
| `wordlists/common.txt` | словарь SecLists, 4752 пути |
| `wordlists/small.txt` | 10 путей для быстрой проверки |

## Требования

- Windows 10 или 11
- PowerShell 5.1 (встроен)
- curl (встроен в Windows 10 начиная с 1803)
- Go 1.26 или новее, только чтобы собрать `ffuf.exe`

## Сборка

```powershell
cd ffuf-master
go build -o ffuf.exe .
```

## Запуск

```powershell
# пассивный аудит, отчёт в audit-report.html
.\audit.cmd https://example.ru

# аудит плюс перебор путей через ffuf
.\audit.cmd https://example.ru -Ffuf

# самоподписанный сертификат
.\audit.cmd https://example.ru -Insecure

# только перебор путей
.\scan.cmd https://example.ru
.\scan.cmd https://example.ru -Fc 404,403 -Rate 20 -Out result.json
```

### Параметры audit.cmd

| Параметр        | По умолчанию           | Смысл                                  |
|-----------------|------------------------|----------------------------------------|
| `-Url`          | обязательный           | адрес сайта, схему можно не указывать  |
| `-Out`          | `audit-report.html`    | имя файла отчёта                       |
| `-Ffuf`         | выключено              | дополнительно прогнать ffuf по словарю |
| `-Wordlist`     | `wordlists\common.txt` | словарь для ffuf                       |
| `-Rate`         | `40`                   | запросов в секунду для ffuf            |
| `-Insecure`     | выключено              | не проверять сертификат                |
| `-Csv`          | выключено              | рядом с HTML писать CSV для трекера    |
| `-CsvDelimiter` | `;`                    | разделитель CSV                        |

### Параметры scan.cmd

| Параметр     | По умолчанию           | Смысл                                                          |
|--------------|------------------------|----------------------------------------------------------------|
| `-Url`       | обязательный           | адрес, `FUZZ` подставится сам                                  |
| `-Wordlist`  | `wordlists\common.txt` | словарь                                                        |
| `-Fc`        | `404`                  | какие коды скрывать                                            |
| `-Rate`      | `40`                   | запросов в секунду                                             |
| `-Threads`   | `20`                   | потоков                                                        |
| `-Header`    | нет                    | свой заголовок, например `-Header "Authorization: Bearer ..."` |
| `-Out`       | нет                    | файл отчёта                                                    |
| `-OutFormat` | `json`                 | `json`, `ejson`, `html`, `md`, `csv`, `ecsv`, `all`            |
| `-Silent`    | выключено              | без баннера и прогресса                                        |

## Что проверяет аудит

| Категория   | Проверки                                                                                                          |
|-------------|-------------------------------------------------------------------------------------------------------------------|
| Заголовки   | HSTS и preload, CSP, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, COOP, COEP, CORP X-Permitted-Cross-Domain-Policies, unsafe-eval в CSP, префиксы cookie                                                             |
| Кликджекинг | X-Frame-Options, CSP frame-ancestors                                                                              |
| Cookie      | Secure, HttpOnly, SameSite                                                                                        |
| TLS         | цепочка, срок, версия протокола, издатель, TLS 1.0 и 1.1                                                          |
| Раскрытие   | `.git/HEAD`, `.env`, бэкапы, `phpinfo`, `server-status`, Server, X-Powered-By, CORS, отражение Origin, мягкая 404 сообщения об ошибках, листинг каталога                                                                                            |
| Формы       | наличие captcha, CSRF-токены, поле телефона, автозаполнение паролей                                               |
| Контент     | смешанный контент, SRI у внешних скриптов, `target=_blank` без noopener, `security.txt`                           |
| Методы      | TRACE, разрешённые PUT и DELETE, редирект с HTTP на HTTPS                                                         |
| Почта       | SPF, DMARC                                                                                                        |
| Пути        | опционально ffuf по словарю                                                                                       |

Всего около 35 проверок, часть выполняется только для HTTPS или при наличии форм.
Оценка сайта считается как процент пройденных проверок, предупреждение даёт половину балла.

## Оценка CVSS

Каждая находка получает ориентировочный балл по CVSS v3.1, в отчёте это отдельная колонка
с вектором в подсказке при наведении.

| Балл       | Уровень  |
|------------|----------|
| 9.0 и выше | Критично |
| 7.0 до 8.9 | Высоко   |
| 4.0 до 6.9 | Средне   |
| 0.1 до 3.9 | Низко    |

Баллы выставлены по типовым векторам для классов «отсутствует заголовок», «раскрыт файл»,
«нет проверки сертификата». Это оценка риска настройки, а не результат эксплуатации:
скрипт ничего не ломает и не подтверждает атаку. Для точной оценки в рамках пентеста
балл считается по конкретному сценарию с учётом того, что реально видит атакующий.

Ориентиры, которые заложены в скрипт:

| Находка                             | Балл |
|-------------------------------------|------|
| `.env` с секретами доступен         | 9.1  |
| CORS `*` вместе с credentials       | 8.1  |
| Любой Origin отражается в CORS      | 8.1  |
| Сайт без HTTPS                      | 7.5  |
| Открыт `.git/HEAD`, бэкап, дамп БД  | 7.5  |
| Разрешены методы PUT, DELETE, PATCH | 7.5  |
| Нет CSRF-токена в формах            | 6.5  |
| Нет редиректа с HTTP на HTTPS       | 6.5  |
| Плохая цепочка или срок сертификата | 5.9  |
| Включён TLS 1.0 или 1.1             | 5.9  |
| Нет DMARC                           | 5.3  |
| Видны сообщения об ошибках          | 5.3  |
| Листинг каталога                    | 5.3  |
| Включён метод TRACE                 | 5.3  |
| Нет X-Frame-Options                 | 4.3  |
| Нет HttpOnly или Secure у cookie    | 4.3  |
| Смешанный контент на HTTPS          | 4.3  |
| `target=_blank` без noopener        | 4.3  |
| unsafe-eval в CSP                   | 4.3  |
| Нет HSTS                            | 3.7  |
| Нет captcha на форме входа          | 3.7  |
| Нет SRI у внешних скриптов          | 3.7  |
| Нет CSP                             | 3.6  |
| Нет COOP                            | 3.1  |
| Мягкая 404                          | 3.1  |

## CSV для трекера

```powershell
.\audit.cmd https://example.ru -Csv
```

Рядом с `audit-report.html` появится `audit-report.csv`. Кодировка UTF-8 с BOM,
разделитель `;`, поэтому Excel открывает файл двойным кликом и не ломает кириллицу.
Для Jira, YouTrack и подобных укажите свой разделитель: `-CsvDelimiter ","`.

| Колонка      | Смысл                                       |
|--------------|---------------------------------------------|
| ID           | `AUD-001`, номер находки                    |
| Приоритет    | P1 критично, P2 высоко, P3 средне, P4 низко |
| Категория    | группа проверки                             |
| Проверка     | название проверки                           |
| Статус       | pass, warn, fail, info                      |
| Уровень      | Критично, Высоко, Средне, Низко             |
| CVSS         | балл v3.1                                   |
| Вектор       | вектор CVSS v3.1                            |
| CWE          | класс слабости                              |
| CVE          | пусто, см. ниже                             |
| Детали       | что найдено                                 |
| Рекомендация | что делать                                  |
| URL          | проверенный адрес                           |

Строки отсортированы по риску: сначала находки по убыванию CVSS, потом информационные,
потом пройденные. Так задачи заводятся в трекер в правильном порядке.

Колонка CVE остаётся пустой намеренно. CVE присваивают конкретным уязвимостям в конкретных
версиях ПО, а здесь находки это классы конфигурации: нет заголовка, открыт `.env`, включён
TRACE. У них нет и не может быть CVE, зато есть CWE, он и заполняется. Если нужен CVE,
надо отдельно определять версии ПО и сверять с базой уязвимостей.

## Чего скрипт не делает

Это важно для честности отчёта, и в сам HTML это тоже вписано.

- **Нагрузка и отказ в обслуживании.** Проверка «упадёт ли сайт» это атака, а не тест.
  Нагрузочное тестирование делают отдельно (k6, Locust) на тестовом контуре, с потолком
  «ожидаемый пик плюс запас», и целью ставят устойчивость, а не падение.
- **Инъекции (SQLi, XSS, RCE) и эксплуатация уязвимостей.** Нужны sqlmap, nuclei и копия
  сайта либо согласованный пентест. Скрипт делает по одному запросу на проверку.
- **Выгрузка базы с персональными данными.** Если база ваша, берите бэкап. Для
  подтверждения SQLi достаточно `@@version`.
- **Массовое создание аккаунтов, обход подтверждения по телефону, рассылка писем.**
  Письма уйдут реальным людям, домен попадёт в спам-листы. Автоматического обхода кода
  здесь нет и не будет: это делается вручную по чеклисту ниже.

## Ручные проверки

То, что нельзя автоматизировать без вреда, проверяется глазами. Ниже короткий список.

**Регистрация по телефону**

1. Код приходит на номер, и без кода войти нельзя.
2. Код не возвращается в ответе API и не попадает в логи.
3. Есть лимит попыток ввода кода, после которого требуется пауза или блокировка.
4. Код живёт ограниченное время и срабатывает один раз.
5. На повторную отправку SMS есть лимит: не чаще раза в минуту и суточный потолок.
6. Смена номера после подтверждения требует повторного подтверждения.
7. Один номер нельзя привязать к неограниченному числу аккаунтов.
8. Полный номер не виден в публичном профиле и в чужих запросах.

**Регистрация и вход**

1. Попробуйте войти с неверным паролем 5 раз подряд: появляется ли задержка или captcha.
2. Посмотрите, приходит ли письмо с подтверждением адреса, и можно ли войти без него.
3. Проверьте, отличается ли ответ сервера для существующего и несуществующего адреса.
4. Оцените, можно ли зарегистрироваться на чужой адрес без подтверждения.

**Загрузка файлов**

1. Загрузите безобидный `test.txt` и посмотрите, по какому пути он доступен.
2. Проверьте, отдаётся ли он как `text/plain`, а не как исполняемый файл.
3. Убедитесь, что файлы лежат вне веб-корня или отдаются через обработчик.

**Почта**

1. Настройте `rua=mailto:` в DMARC и смотрите отчёты о попытках подделки.
2. Проверьте, есть ли лимит на отправку писем из формы обратной связи.
